## 通知 A —— `openroboto-backend` / `openroboto-cli` 的负责人（需要动手）

> 发到：团队频道，@ 两个仓的负责人
> 时机：v0.7.0 上 PyPI 之后

**Subject: openroboto-protocol 0.7.0 is on PyPI — please bump your pin (backend first)**

0.7.0 is published. It is additive: no existing field changed shape, no vocabulary
word was removed, and the on-chain encoding of a payload without the two new keys
is byte-for-byte what it always was. Full entry, written per audience:
`CHANGELOG.md`.

What is new for you:

- `commitment`: `cid` (`competition_id`, int) and `m` (`model_hash`) on the
  payload, plus `Track` and `check_payload()`. Both keys are omitted when unset,
  and a payload without `cid` still resolves as `(sim, round_num=r)`.
- `status`: `SeasonStatus` and `InvalidReason`, each with a `*_VALUES` tuple —
  build the `CHECK` constraints from the package, not from a hand-typed literal.
  `INVALID_REASON_VALUES` is exactly the word list already in migration 0004.
  There is deliberately **no** new submission status.
- `schemas`: `EpisodeResult` / `MediaRef` / `EpisodeFailure` for
  `POST /real/tasks/{id}/episodes`. `ScoreSubmission` and the whole simulation
  scoring path are untouched.
- `model_format`: `check_lingbot_layout()` for LingBot-VLA 2.0, alongside the
  openpi rules. `check_checkpoint_layout()` is byte-for-byte unchanged.

**Order matters, do not swap it.** Backend first, CLI second. Once the CLI ships,
miners can start writing commitments that carry `cid`, and the backend has to
already understand them — the fee for those submissions is paid on chain before
anyone can fix a misordered rollout.

1. `openroboto-backend`: `openroboto-protocol[schemas]==0.5.0` → `==0.7.0`,
   `uv lock`, CI, deploy through CI/CD.
   ⚠️ You are crossing two versions. Two reds are **expected and by design**, not
   regressions: `test_protocol_weight_parity.py` is a self-expiring case that goes
   red the moment the package carries `weights` (its failure message lists the
   three things to do), and the five parity tests that skip wholesale when the
   package is absent will actually run — if they go red, that is the most valuable
   output of this bump, since it means a hand-copied mirror has drifted.
   **Do not add `skip` to make CI green.** Anything else red is a real regression.
2. `openroboto-cli`: `openroboto-protocol==0.6.0` → `==0.7.0`, `uv lock`, CI, then
   bump the CLI's own version and republish it — a miner installs the CLI, so
   without that step nobody receives this release.

Rollback: steps 1–2 are reversible (put the pin back, `uv lock`, redeploy).
Republishing the CLI is not — a PyPI version number cannot be reused.

## 通知 B —— 评测方 worker 与外部验证者（不需要动手）

> 发到：评测方的对接频道 / 邮件；外部验证者按现有渠道
> 时机：随时

**Subject: openroboto-protocol 0.7.0 — no action needed on your side**

We are releasing version 0.7.0 of the shared protocol package today. **Nothing in
it requires anything from you**, and we are writing only so that the release is
not something you hear about second-hand.

- You do not install this package, so a version bump on our side cannot reach
  your machines.
- No HTTP response shape you read changes. `/api/weights` in particular is
  byte-identical.
- No on-chain payload written by software you run changes. Commitments produced by
  the current miner CLI encode to exactly the same bytes; we verify that against
  295 real bytes from block 8808332 on every commit, and that check is what would
  block the release if it ever stopped being true.
- Nothing about the task suites, the scoring path or the submission lifecycle
  words moves. The additions are for the upcoming real-robot track and for a
  second base model, and both are opt-in per competition.

The one thing worth knowing for later: when a real-robot season opens, the
episode-report body gains an explicit failure classification with exactly two
values, `hw_failed` and `model_error`, because that distinction decides refunds.
We will come to you with the endpoint and a schedule well before it matters, and
we do not set deadlines for your side (`openroboto-evaluation/SCOPE.md`).

## 不通知谁，为什么

- **矿工**：这一版对他们零动作（编码逐字节不变），而他们装的是 CLI 不是这个包。
  面向矿工的发布说明属于 **CLI 那次发布**（通知 A 第 2 步），不在这里发，
  免得他们收到一条「有个包升级了」但不知道要不要动手的消息。
- **前端**：响应体字段名一个字没改，没有可通知的内容。
